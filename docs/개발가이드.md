# 개발 가이드

래더 협동 보스 레이드의 코드를 직접 보고 고칠 때 참고하는 문서입니다.
빌드 도구 없이 HTML, CSS, JavaScript 파일만으로 동작합니다. 파일을 고쳐서 GitHub `main` 브랜치에 올리면 1~2분 뒤 GitHub Pages 에 반영됩니다.

## 폴더 구조

```
index.html            화면 구조(HTML). 패널, 버튼, 입력 칸의 위치와 문구
privacy.html          로그인·개인정보 안내 페이지
ladder-test.html      브라우저 수집 가능 여부 테스트 페이지
css/style.css         디자인. 맨 위 :root 의 색 변수만 바꿔도 전체 색이 바뀜
firebase-config.js    Firebase 연결 값 (비워두면 브라우저 저장)
database.rules.json   Firebase 보안 규칙 (콘솔에 붙여넣는 용도)
js/
  main.js             시작점: 모든 모듈을 불러와 init() 을 순서대로 실행
  core/               화면과 상관없는 핵심
    app.js            ★ 공유 상태 App (현재 레이드, 기록, 로그인 사용자 등 모든 "바뀌는 값")
    game-data.js      ★ 게임 수치: 난이도, 보스 스킬, 역할 스킬, 장비, 룰렛, 보스 이름
    state.js          공통 도우미($, esc, fmt)와 고정값(MODE 등)
    store.js          저장소: 브라우저(localStorage) 또는 Firebase 에 쓰기
    logic.js          게임 규칙 계산 (compute 함수)
    boot.js           시작: 데이터 불러오기, 백업 저장·불러오기, Firebase 연결
  ui/                 화면 그리기
    render.js         메인 화면 (보스 HUD, 공략대 현황, 전투 기록)
    me-info.js        왼쪽 내 정보 창 (체력·스킬 게이지·착용 장비·계산식)
    setup.js          새 레이드 만들기, 레이드 종료, 보스 이름
    overlay.js        방송 오버레이 (데미지 숫자, 하단 알림, 오버레이 주소)
    info-window.js    정보 창(보스 스킬·역할 스킬·장비·룰렛·규칙)과 시작 전 수치 설정
    history.js        오버레이 스킬 목록, 레이드 기록, 명예의 전당
    dungeon.js        던전(진행 중인 공략대 목록), 공략대·개인 랭킹 창
  features/           기능별 동작
    actions.js        결과 반영, 룰렛, 참가, 공략대원 추가
    gear-roulette.js  장비 룰렛, 인벤토리
    role-skill.js     역할 스킬 사용 바, 역할·입장료 수정
    ladder.js         데미지 입력 아래 래더 자동 수집 상태와 래더 아이디 표
    ladder-browser.js 프로그램 없이 레이드 화면 탭이 수집기 역할을 하는 브라우저 수집
    party.js          초대 코드로 참가, 공략대원 내보내기
    auth.js           구글 로그인, 내 프로필, 운영자 권한, 로그인 정보 삭제
  lib/
    ladder-local.js   스타크래프트 로컬 래더 서버 찾기·조회 (일반 스크립트, 테스트 페이지와 공용)
collector/
  ladder-collector.cmd  래더 점수 수집기 (Windows, 스타크래프트가 켜진 PC에서 실행)
```

## 코드 구조 (모듈)

빌드 도구 없이 브라우저 기본 기능인 **ES 모듈**(`import` / `export`)을 씁니다. 설치할 것은 없습니다.

- **파일마다 필요한 것만 가져다 씁니다.** 각 파일 맨 위의 `import { ... } from '@app/...'` 를 보면 그 파일이 어디의 무엇에 기대는지 바로 알 수 있고, 맨 아래 `export { ... }` 가 다른 파일에 내주는 목록입니다.
- **바뀌는 값은 모두 `App` 한 곳에 있습니다** (`js/core/app.js`). 현재 레이드는 `App.raid`, 기록은 `App.events`, 로그인 사용자는 `App.authUser` 처럼 씁니다. 어떤 파일이 값을 바꾸면 다른 파일도 같은 값을 봅니다. 새 상태 값이 필요하면 `app.js` 의 `App` 에 한 줄 추가하세요.
- **`init()`** — 각 파일의 "처음 한 번" 할 일(버튼 연결, 초기값)은 `export function init(){ ... }` 안에 있습니다. `js/main.js` 가 파일 순서대로 한 번씩 부릅니다. 함수 정의는 순서와 상관없고, `init()` 안의 일만 순서대로 실행됩니다.
- **`@app/...` 경로** — `index.html` 의 `<script type="importmap">` 이 `@app/core/logic.js` 같은 이름을 실제 파일 `./js/core/logic.js?v=...` 로 연결합니다. 파일을 고친 뒤 배포할 때 `index.html` 의 `?v=` 숫자를 모두 같은 새 값으로 바꾸면 방문자 브라우저가 옛 파일 대신 새 파일을 받습니다.

새 파일 추가하기:

1. 예: `js/features/shop.js` 를 만들고 맨 위에 `import { App } from '@app/core/app.js';` 와 필요한 함수 import 를 씁니다.
2. 다른 파일에서 쓸 함수에 `export` 를 붙이고, 처음 한 번 할 일은 `export function init(){ ... }` 에 넣습니다.
3. `index.html` 의 importmap 에 `"@app/features/shop.js": "./js/features/shop.js?v=..."` 를 추가합니다.
4. `js/main.js` 에 `import * as shop from '@app/features/shop.js';` 를 추가하고 `modules` 배열에 넣습니다. (`boot.js` 보다 앞)

내 컴퓨터(localhost)에서 열면 개발 편의를 위해 `App` 과 모든 함수가 전역으로도 꺼내져 있어서, 브라우저 콘솔에서 `compute(raid, events)` 처럼 바로 확인할 수 있습니다. 실제 사이트에서는 꺼내지 않습니다.

## 자주 하는 수정

| 하고 싶은 것 | 고칠 곳 |
|---|---|
| 난이도별 보스 HP, 분노, 회복률 | `js/core/game-data.js` 의 `PRESETS` |
| 보스 스킬 이름·확률·수치 | `js/core/game-data.js` 의 `BOSS_SETS` |
| 보스 이름 추가 | `js/core/game-data.js` 의 `BOSS_BY_RACE` |
| 역할 스킬 이름·수치 | `js/core/game-data.js` 의 `DEFAULT_ROLE_SKILLS` |
| 스킬 게이지 | `js/core/game-data.js` 의 `DEFAULT_GAUGE` |
| 룰렛 결과 이름·확률 | `js/core/game-data.js` 의 `ITEMS` |
| 장비 이름·수치, 장비 룰렛 확률 | `js/core/game-data.js` 의 `GEAR`, `DEFAULT_GEAR_ROLL` |
| 장비 등급 확률·내구도·능력치 배율 | `js/core/game-data.js` 의 `GEAR_GRADES` |
| 체인 보너스, 장비 룰렛 비용 | `js/core/game-data.js` 의 `DEFAULT_SETTINGS` |
| 공략대원 기본 체력, 부활 체력 | `js/core/game-data.js` 의 `PARTY_HP`, `REVIVE_HP` |
| 화면 문구, 버튼 이름 | `index.html` (일부 문구는 `js/ui/render.js`, `js/ui/info-window.js`) |
| 색, 글꼴, 간격 | `css/style.css` |
| 규칙 자체(계산 방식) | `js/core/logic.js` 의 `compute` |

`js/core/game-data.js` 의 값은 **새로 여는 레이드의 기본값**입니다. 진행 중인 레이드에는 시작할 때의 값이 저장되어 있어서 바뀌지 않습니다.

## 데이터가 움직이는 방식

1. 레이드를 시작하면 `App.raid` 객체 하나가 저장됩니다. 보스 이름, 난이도 값(`cfg`), 보스 스킬, 역할 스킬, 설정(`settings`), 공략대원과 역할·입장료(`roster`)가 들어 있습니다.
2. 결과 입력, 룰렛, 장비 룰렛, 역할 스킬 사용은 모두 **기록(event)** 한 줄로 추가됩니다. 기록에는 결과만 들어가고, 보스 HP 같은 계산값은 저장하지 않습니다.
3. `js/core/logic.js` 의 `compute(raid, events)` 가 기록을 처음부터 순서대로 다시 계산해서 보스 HP, 분노, 공략대원 체력, 게이지, 장비를 만듭니다.
4. `js/ui/render.js` 의 `render()` 가 그 결과로 화면을 그립니다.

그래서 기록을 **취소**하면 그 이후 결과가 자동으로 다시 계산됩니다. 보스 스킬의 무작위 결과도 기록 내용으로 정해지기 때문에 어느 화면에서 계산해도 같습니다.

기록 종류(`type`):

| type | 내용 | 주요 값 |
|---|---|---|
| `game` | 래더 결과 | `points`(+승리/−패배), `multi`, `same`, `banned` |
| `roulette` | 룰렛 결과 | `item` (`ITEMS` 의 id) |
| `gear` | 장비 룰렛 | `item` (`'weapon:2'` 같은 키 또는 `'none'`), `grade` (`common`/`rare`/`epic`/`legend`), `cost` |
| `equip` | 인벤토리 장착·해제 | `item` (장착할 장비를 얻은 `gear` 기록의 id, 또는 `'off:weapon'` 같은 해제) |
| `party` | 공략대 구성 기록 (계산에는 영향 없음) | `action` (`join` 참가, `kick` 내보냄, `role` 역할 변경, `fee` 입장료 변경), `role`, `fee` |
| `role` | 역할 스킬 사용 | 없음 (공략대원의 역할로 결정) |

## 래더 자동 수집

스타크래프트: 리마스터는 로그인하면 PC 안에 래더 조회용 웹 서버(`http://127.0.0.1:<포트>/web-api/...`)를 엽니다. `collector/ladder-collector.cmd` 는 이 서버로 공략대원 아이디를 조회합니다.

1. 스타크래프트 프로세스가 열어 둔 포트를 찾아 `/web-api/v1/gateway` 로 확인합니다.
2. Firebase 의 `coop/raids` (진행 중인 모든 공략대)에서 공략대원과 `roster.<이름>.ladder`(아이디), `gw`(서버: 30 한국, 45 아시아, 10/11 미국, 20 유럽)를 읽습니다.
3. 20초마다 `/web-api/v2/aurora-profile-by-toon/<아이디>/<서버>?request_flags=scr_mmtooninfo` 에서 이번 시즌 1:1 `rating`, `wins`, `losses` 를 읽습니다.
4. 승+패 수가 늘면 점수 차이로 `type:'game', auto:true` 기록을 추가합니다. 처음 본 값은 기준점으로만 저장합니다.
5. 공략대원별 마지막 값은 `coop/ladder/<레이드ID>`, 수집기 상태는 `coop/collector` 에 씁니다.

비공식 기능이라 게임 패치로 응답 형식이 바뀌면 수집기의 `Get-Ladder` 함수를 고치면 됩니다. 수집기 맨 위 설정에서 조회 간격과 사이트 주소를 바꿀 수 있습니다.

## 내 컴퓨터에서 미리 보기

`index.html` 을 더블클릭해도 열리지만, 브라우저에 따라 파일을 막을 수 있어서 간단한 서버로 여는 게 안전합니다.

```
cd SC_Ladder_Co-op_Raid
python -m http.server 8000
```

브라우저에서 `http://localhost:8000` 을 열면 됩니다. 파일을 고친 뒤에는 Ctrl+F5 로 새로고침하세요.

## 배포

`main` 브랜치에 커밋을 올리면 GitHub Actions 의 "pages build and deployment" 가 자동으로 돌고, 1~2분 뒤 사이트에 반영됩니다. 짧은 간격으로 여러 번 올리면 앞의 배포가 취소되고 마지막 것만 반영되니, 반영이 안 된 것 같으면 레포의 **Actions** 탭에서 마지막 배포가 끝났는지 확인하세요.

## 데이터 저장 위치

- **Firebase 를 연결하지 않았을 때**: 그 브라우저의 localStorage 에 `sc-boss-raid:coop`(현재 레이드), `sc-boss-raid:history:coop`(지난 레이드) 이름으로 저장됩니다. 다른 기기와 공유되지 않습니다.
- **로그인 정보**: `users/<uid>` 에 프로필(name, ladder, gw), `admins/<uid>` 에 운영자 표시가 저장됩니다. 공략대원 기록(`roster`)에는 참가한 계정의 `uid` 가 함께 들어갑니다.
- **Firebase 를 연결했을 때**: Realtime Database 의 `coop/raids/<레이드ID>`(공략대마다 하나, `squad` 가 공략대 번호), `coop/events/<레이드ID>`, `coop/history/<레이드ID>` 에 저장되고 모든 화면에 실시간으로 반영됩니다. 초대 코드는 `invites/coop/<레이드ID>`, 참가 확인은 `joins/coop/<레이드ID>/<uid>` 입니다.
- 나중에 "래더 보스 레이드 대전" 버전을 만들면 `js/core/state.js` 의 `MODE` 를 `'versus'` 로 바꾼 별도 페이지를 쓰면 데이터가 섞이지 않습니다.
