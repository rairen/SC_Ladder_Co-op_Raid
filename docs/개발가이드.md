# 개발 가이드

래더 협동 보스 레이드의 코드를 직접 보고 고칠 때 참고하는 문서입니다.
빌드 도구 없이 HTML, CSS, JavaScript 파일만으로 동작합니다. 파일을 고쳐서 GitHub `main` 브랜치에 올리면 1~2분 뒤 GitHub Pages 에 반영됩니다.

## 폴더 구조

```
index.html            화면 구조(HTML). 패널, 버튼, 입력 칸의 위치와 문구
css/style.css         디자인. 맨 위 :root 의 색 변수만 바꿔도 전체 색이 바뀜
firebase-config.js    Firebase 연결 값 (비워두면 브라우저 저장)
database.rules.json   Firebase 보안 규칙 (콘솔에 붙여넣는 용도)
js/
  game-data.js        ★ 게임 수치: 난이도, 보스 스킬, 역할 스킬, 장비, 룰렛, 보스 이름
  state.js            공통 도우미($, esc, fmt)와 화면 상태 변수
  store.js            저장소: 브라우저(localStorage) 또는 Firebase 에 쓰기
  logic.js            게임 규칙 계산 (compute 함수)
  render.js           메인 화면 그리기 (보스 HUD, 파티 현황, 전투 기록)
  setup.js            새 레이드 만들기, 레이드 종료, 보스 이름
  actions.js          버튼 동작: 결과 반영, 룰렛, 참가, 파티원 추가
  gear-roulette.js    장비 룰렛
  overlay.js          방송 오버레이 (데미지 숫자, 하단 알림, 오버레이 주소)
  role-skill.js       역할 스킬 사용 바, 파티 현황의 역할·입장료 수정
  info-window.js      정보 창(보스 스킬·역할 스킬·장비·룰렛·규칙)과 시작 전 수치 설정
  ladder.js           래더 자동 수집 패널 (래더 아이디, 수집기 상태)
  auth.js             구글 로그인, 내 프로필(닉네임·게임 아이디), 운영자 권한
  history.js          오버레이 스킬 목록, 레이드 기록, 명예의 전당
  boot.js             시작: 데이터 불러오기, 백업 저장·불러오기, Firebase 연결
collector/
  ladder-collector.cmd  래더 점수 수집기 (Windows, 스타크래프트가 켜진 PC에서 실행)
```

`index.html` 아래쪽에서 `js/` 파일을 위 순서대로 읽습니다. 앞 파일에서 만든 변수와 함수를 뒤 파일이 쓰기 때문에 **순서를 바꾸면 안 됩니다**. 새 파일을 추가할 때는 그 파일이 쓰는 것보다 뒤에, `boot.js` 보다는 앞에 넣으세요.

## 자주 하는 수정

| 하고 싶은 것 | 고칠 곳 |
|---|---|
| 난이도별 보스 HP, 분노, 회복률 | `js/game-data.js` 의 `PRESETS` |
| 보스 스킬 이름·확률·수치 | `js/game-data.js` 의 `BOSS_SETS` |
| 보스 이름 추가 | `js/game-data.js` 의 `BOSS_BY_RACE` |
| 역할 스킬 이름·수치 | `js/game-data.js` 의 `DEFAULT_ROLE_SKILLS` |
| 스킬 게이지 | `js/game-data.js` 의 `DEFAULT_GAUGE` |
| 룰렛 결과 이름·확률 | `js/game-data.js` 의 `ITEMS` |
| 장비 이름·수치, 장비 룰렛 확률 | `js/game-data.js` 의 `GEAR`, `DEFAULT_GEAR_ROLL` |
| 승리 유형 배율, 체인 보너스, 장비 룰렛 비용 | `js/game-data.js` 의 `DEFAULT_SETTINGS` |
| 파티원 기본 체력, 부활 체력 | `js/game-data.js` 의 `PARTY_HP`, `REVIVE_HP` |
| 화면 문구, 버튼 이름 | `index.html` (일부 문구는 `js/render.js`, `js/info-window.js`) |
| 색, 글꼴, 간격 | `css/style.css` |
| 규칙 자체(계산 방식) | `js/logic.js` 의 `compute` |

`game-data.js` 의 값은 **새로 여는 레이드의 기본값**입니다. 진행 중인 레이드에는 시작할 때의 값이 저장되어 있어서 바뀌지 않습니다.

## 데이터가 움직이는 방식

1. 레이드를 시작하면 `raid` 객체 하나가 저장됩니다. 보스 이름, 난이도 값(`cfg`), 보스 스킬, 역할 스킬, 설정(`settings`), 파티원과 역할·입장료(`roster`)가 들어 있습니다.
2. 결과 입력, 룰렛, 장비 룰렛, 역할 스킬 사용은 모두 **기록(event)** 한 줄로 추가됩니다. 기록에는 결과만 들어가고, 보스 HP 같은 계산값은 저장하지 않습니다.
3. `js/logic.js` 의 `compute(raid, events)` 가 기록을 처음부터 순서대로 다시 계산해서 보스 HP, 분노, 파티원 체력, 게이지, 장비를 만듭니다.
4. `js/render.js` 의 `render()` 가 그 결과로 화면을 그립니다.

그래서 기록을 **취소**하면 그 이후 결과가 자동으로 다시 계산됩니다. 보스 스킬의 무작위 결과도 기록 내용으로 정해지기 때문에 어느 화면에서 계산해도 같습니다.

기록 종류(`type`):

| type | 내용 | 주요 값 |
|---|---|---|
| `game` | 래더 결과 | `points`(+승리/−패배), `multi`, `same`, `banned` |
| `roulette` | 룰렛 결과 | `item` (`ITEMS` 의 id) |
| `gear` | 장비 룰렛 | `item` (`'weapon:2'` 같은 키 또는 `'none'`), `cost` |
| `role` | 역할 스킬 사용 | 없음 (파티원의 역할로 결정) |

## 래더 자동 수집

스타크래프트: 리마스터는 로그인하면 PC 안에 래더 조회용 웹 서버(`http://127.0.0.1:<포트>/web-api/...`)를 엽니다. `collector/ladder-collector.cmd` 는 이 서버로 파티원 아이디를 조회합니다.

1. 스타크래프트 프로세스가 열어 둔 포트를 찾아 `/web-api/v1/gateway` 로 확인합니다.
2. Firebase 의 `coop/raid` 에서 파티원과 `roster.<이름>.ladder`(아이디), `gw`(서버: 30 한국, 45 아시아, 10/11 미국, 20 유럽)를 읽습니다.
3. 20초마다 `/web-api/v2/aurora-profile-by-toon/<아이디>/<서버>?request_flags=scr_mmtooninfo` 에서 이번 시즌 1:1 `rating`, `wins`, `losses` 를 읽습니다.
4. 승+패 수가 늘면 점수 차이로 `type:'game', auto:true` 기록을 추가합니다. 처음 본 값은 기준점으로만 저장합니다.
5. 파티원별 마지막 값은 `coop/ladder/<레이드ID>`, 수집기 상태는 `coop/collector` 에 씁니다.

비공식 기능이라 게임 패치로 응답 형식이 바뀌면 수집기의 `Get-Ladder` 함수를 고치면 됩니다. 수집기 맨 위 설정에서 조회 간격과 사이트 주소를 바꿀 수 있습니다.

## 내 컴퓨터에서 미리 보기

`index.html` 을 더블클릭해도 열리지만, 브라우저에 따라 파일을 막을 수 있어서 간단한 서버로 여는 게 안전합니다.

```
cd SC_Ladder_Co-op_Raid
python -m http.server 8000
```

브라우저에서 `http://localhost:8000` 을 열면 됩니다. 파일을 고친 뒤에는 Ctrl+F5 로 새로고침하세요.

## 배포

`main` 브랜치에 커밋을 올리면 GitHub Actions 의 "pages build and deployment" 가 자동으로 돌고, 1~2분 뒤 사이트에 반영됩니다. 짧은 간격으로 여러 번 올리면 앞의 배포가 취소되고 마지막 것만 반영되니, 반영이 안 된 것 같으면 레포의 **Actions** 탭에서 마지막 배포가 끝났는지 확인하세요.

## 데이터 저장 위치

- **Firebase 를 연결하지 않았을 때**: 그 브라우저의 localStorage 에 `sc-boss-raid:coop`(현재 레이드), `sc-boss-raid:history:coop`(지난 레이드) 이름으로 저장됩니다. 다른 기기와 공유되지 않습니다.
- **로그인 정보**: `users/<uid>` 에 프로필(name, ladder, gw), `admins/<uid>` 에 운영자 표시가 저장됩니다. 파티원 기록(`roster`)에는 참가한 계정의 `uid` 가 함께 들어갑니다.
- **Firebase 를 연결했을 때**: Realtime Database 의 `coop/raid`, `coop/events/<레이드ID>`, `coop/history/<레이드ID>` 에 저장되고 모든 화면에 실시간으로 반영됩니다.
- 나중에 "래더 보스 레이드 대전" 버전을 만들면 `js/state.js` 의 `MODE` 를 `'versus'` 로 바꾼 별도 페이지를 쓰면 데이터가 섞이지 않습니다.
